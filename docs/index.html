quant-portfolio

quant-portfolio is a set of study implementations of standard quantitative-finance models: option pricing, volatility forecasting, VaR and expected shortfall, fixed income, pairs trading, credit scoring, portfolio optimisation, execution scheduling, volatility surfaces and regime detection. Each area is written in Python with equity conventions and again with FX conventions. The option-pricing and VaR libraries also have C++ and Rust ports, tested against the Python code and, for options, against an mpmath oracle. All results on this site come from seeded synthetic data unless a page names a dataset. The code has not been used on a live book.

The 10 project areas

01

Options Pricing & Greeks

Black-Scholes / Garman-Kohlhagen closed form, analytic and finite-difference Greeks, CRR and Leisen-Reimer trees, Crank-Nicolson and ALO for American exercise, discrete dividends, Bachelier, SABR, higher-order Greeks, FX smiles, premium styles and cuts, implied vol by a safeguarded Halley iteration, Monte Carlo cross-checks. C++ and Rust ports.

02

Volatility Modelling

GARCH-family forecasting of realized volatility, clustering and mean reversion, HAR-RV, forecast validation against a naive benchmark.

03

VaR / Expected Shortfall

Historical, age-weighted, parametric (Cornish-Fisher) and Monte Carlo VaR with full book revaluation; Kupiec and Christoffersen backtests and a Basel traffic light for any window; Euler risk attribution, FRTB IMA pieces, stressed VaR, EVT and t-copula Monte Carlo, option P&L explain and limits. C++ and Rust ports that reprice European option legs in full in each scenario.

04

Fixed Income

Bond pricing, yield-to-maturity solving, duration/convexity/DV01, yield curve construction, day-count conventions; OIS multi-curve, caps and swaptions, Hull-White, float-float cross-currency swaps.

05

Statistical Pairs Trading

Cointegration testing, hedge-ratio estimation, z-score entry/exit, market-neutral spread construction and backtesting. A pre-registered FX pairs study on ECB data has a training-period result only.

06

Credit Risk

Probability-of-default modelling, discrimination and calibration validation, expected-loss estimation; LGD and EAD, margin of conservatism, migration, CDS bootstrap, CVA/DVA and SA-CCR.

07

Portfolio Optimisation

Mean-variance, minimum-variance and risk-parity allocation, constrained optimisation, marginal/component risk attribution; HRP, robust and resampled MVO, costs and turnover, factor model, tracking error, Sharpe-ratio tests.

08

Algorithmic Execution

TWAP/VWAP/POV scheduling from a forecast volume curve, Almgren-Chriss under linear and power-law impact (closed form and a Newton solver), impact charged on each bucket's participation so cost does not depend on slicing, implementation shortfall and TCA. A schedule-level cost model on a bucket simulator; costs shown are model-implied.

09

Volatility Surfaces

Raw-SVI smile/skew surface construction with Durrleman no-arbitrage checks, Heston stochastic volatility (little-trap characteristic function) with Monte Carlo pricing; SSVI and eSSVI, Dupire local vol, Bates.

10

Regime-Switching Strategies

Regime detection, regime-conditional signals, walk-forward validation against overfitting to hindsight-obvious regimes.

Foundations and engines

F1–F3

Foundations

Single-asset risk metrics on synthetic data, a moving-average backtest with fills modelled at t+1, and a Black-Scholes rebuild using only math.erfc, checked against a Monte Carlo pricer.

C++ / Rust

Compiled ports

C++23 and Rust ports of the options and VaR libraries. No runtime dependencies beyond the standard library; C++ tests use GoogleTest. The VaR ports revalue linear positions and reprice European option legs in full. The Python packages call them through engine="cpp" or engine="rust". The shared core holds one Black-Scholes kernel in cost-of-carry form per language (Python, C++, Rust), which the equity and FX option code wraps with no output bit changed; vectorised C++ batches and NumPy array functions sit on it. It also has Philox, O(n) quantiles and blocked GEMM. The engines are ports of the Python design, not independent derivations. Shared code lives in cpp/core and rust/core, and the qp-cpp and qp-rust packages in bindings/ call the engines from Python.

Docs

Documentation contract

Each project states why it uses its model, what it assumes, how it was validated, where it fails and how it is meant to be used. Changes are listed in the changelog.

Builds and checks

Install

Hash-checked

Every Python install in CI comes from uv.lock with sha256 hashes checked; a file that does not match stops the job. The C++ engines install as the CMake package QuantPortfolio, and CI builds wheels of both bindings as artefacts.

Latency

Same-runner A/B

C++ and Rust share one timing method: median with p10/p90 over at least 31 samples. CI runs the old and new commit in turns on one runner and fails only on a slowdown above 25% whose bands do not overlap.

Research

One look, logged trials

Every training run is logged to trials.jsonl. The two signed forward studies are scored once, on or after 2028-11-13; the momentum test has about 13% power at a Sharpe of 0.4, so a fail is the expected outcome.

Quick start

Use a virtual environment outside the clone. Full commands are in CONTRIBUTING.md.

git clone https://github.com/AshJha0/quant-portfolio && cd quant-portfolio
python -m venv ../venv-qp && . ../venv-qp/bin/activate
cd python/equity/01-options-pricing
python -m pip install -c ../../../requirements/ci-constraints.txt -e ".[dev]"
python -m pytest -q
# a C++ engine, with the gcc preset (build tree under build/gcc)
cd cpp/equity-options-engine
cmake --preset gcc && cmake --build --preset gcc && ctest --preset gcc
# a Rust engine, from the Cargo workspace
cd rust && cargo test --release --locked -p eq-var-engine
