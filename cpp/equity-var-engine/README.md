# Equity VaR Engine (C++23)

A dependency-free C++23 port of the Python engine
[`python/equity/03-var-es-engine`](../../python/equity/03-var-es-engine).
It computes VaR, Expected Shortfall and backtests for a book described by a
vector of linear factor exposures, plus European options on those factors.
The linear part is `P&L = w . r`; option legs are repriced in full
(Black-Scholes-Merton) in every historical or Monte Carlo scenario, see
[Option VaR](#option-var-full-revaluation).

```
returns panel (T x n) -- sample / EWMA covariance -- Cholesky (capped jitter, PSD repair)
   |
   +-- Historical VaR: order statistic / BRW age-weighted / per-factor FHS
   +-- Parametric VaR: normal / variance-matched Student-t / Cornish-Fisher
   +-- Monte Carlo VaR: MVN and multivariate t, per-path Philox4x32-10, threaded bootstrap SE
   +-- Expected Shortfall: Acerbi-Tasche with the fractional atom / closed forms
   +-- Backtesting: Kupiec POF, Christoffersen IND/CC, Acerbi-Szekely Z2
   +-- Basel traffic light: binomial zones on any window and alpha
```

## Conventions

`alpha` is the tail probability everywhere (0.01 = 99 % VaR). Values
outside (0, 0.5) throw `std::invalid_argument`. VaR and ES are positive
losses. The empirical VaR is the order statistic L(m) of the losses, with
m = ceil(n alpha - 1e-9), and ES is the Acerbi-Tasche average with the
fractional atom. Every public function throws `std::invalid_argument` on
NaN, infinite, empty or out-of-domain input. `docs/METHODOLOGY.md` states
each convention in full.

## Why a C++ engine when the Python stack exists?

- **Per-call cost.** Historical and parametric VaR on an updated exposure
  vector cost microseconds (see Latency below), so a desk can recompute on
  each trade.
- **Hot-path API.** `eqvar/kernels.hpp` gives noexcept `try_*` kernels that
  return `std::expected<T, eqvar::Error>`, take their work buffers from the
  caller and never allocate once those are sized.
- **Repeatability.** Each Monte Carlo path draws from its own
  Philox4x32-10 stream `(seed, path)` with AS 241 normals
  (`qp/philox.hpp`), so a seed gives the same bits on any thread count and
  the same numbers as the Rust engine (since milestone v2.1; before, one
  `std::mt19937_64` stream with Acklam normals). Never
  `std::normal_distribution`. A seed repeats exactly on one platform. Across
  platforms the last bits can differ: `std::log`, `std::exp` and `std::erfc`
  are not correctly rounded, and glibc, MSVC and Apple libm differ.
- **No dependencies.** `<random>`, `<cmath>` and the STL only. The normal
  inverse CDF, log-gamma (Lanczos, thread-safe), incomplete beta and gamma,
  Student-t quantile, binomial CDF and a Jacobi eigen solver are in `src/`.

## Quickstart

```bash
cd cpp/equity-var-engine
cmake -S . -B build                 # GTest from the system, else fetched (v1.15.2)
cmake --build build -j
ctest --test-dir build              # 136 tests, about 13 s serial with GCC 15 -O3
./build/bench_eqvar --out /tmp/eqvar_latency.json
```

through. `CMAKE_BUILD_TYPE` defaults to Release. Sanitizer builds skip the
allocation-counting test binary (134 tests run there), because the sanitizer runtime
defines `operator new` itself.

```cpp
#include "eqvar/backtest.hpp"
#include "eqvar/historical.hpp"
#include "eqvar/monte_carlo.hpp"
#include "eqvar/parametric.hpp"

using namespace eqvar;
Matrix cov = ewma_covariance(returns_panel, 0.94);              // (T x n) -> (n x n)
double v_h = historical_var(pnl, 0.01);                         // 99 % 1d, order statistic
TailRisk f = filtered_historical_var_es(returns_panel, w, 0.01); // per-factor FHS
double v_p = parametric_var(w, cov, 0.01, Dist::StudentT, 6.0);
MonteCarloResult mc = monte_carlo_var(w, cov, 0.01, 100'000, Dist::StudentT, 6.0, /*seed=*/42);
// mc.var, mc.es, mc.var_se (bootstrap), mc.var_se_kde (diagnostic)
BaselResult tl = basel_traffic_light({.n_obs = 250, .n_exceptions = 5, .alpha = 0.01});
// yellow, multiplier 3.40
```

Hot path: the same estimators without exceptions or allocation.

```cpp
#include "eqvar/kernels.hpp"

std::vector<double> ws(max_scenarios);                  // sized once
Result<double> v = try_historical_var(pnl, 0.01, ws);   // noexcept
if (!v) log(message(v.error()));                        // formats only on error

std::vector<double> L(n * n), scratch(n * n);
Result<double> jitter = try_cholesky_lower(cov, L, scratch);   // start of day
McVarWorkspace mc;
mc.reserve(n, 10'000);
Result<MonteCarloResult> r =
    try_monte_carlo_var_factored(w, L, 0.01, 10'000, Dist::Normal, 6.0, seed, 200, mc);
```

Every throwing function is now a thin wrapper over its `try_*` form and
keeps its exception types and messages. A program that prints 5,557
legacy-API results and exception texts in hex-float gave identical output
against the library before and after that change, with GCC 15.2 and
Clang 21.1. One later change moves numbers on purpose: since milestone v2.1
the linear Monte Carlo kernel computes each path as one O(n) dot product
with v = L'w, so Monte Carlo VaR and ES match 2.0.0 and the two-step
`simulate_factor_returns` + `portfolio_pnl` path to 1e-12 relative, not bit
for bit (docs/METHODOLOGY.md, `docs/MIGRATION.md` at the repository root).

## Shared core, presets and C++26

The normal cdf and inverse, the special functions, the Gamma sampler, the dense matrix with Cholesky, eigen and PSD repair, and the scenario P&L kernel come from `qp::core`, the
header-only library in `cpp/core` (see `cpp/core/README.md`). This engine
keeps its own headers and API; moved names are using-declarations. The
CMake file adds the core with `add_subdirectory(../core)` unless a parent
project already did.

`CMakePresets.json` defines the presets `gcc`, `clang`, `gcc16-cxx26`,
`asan`, `tsan` and `msvc`. From this directory:

```bash
cmake --preset clang
cmake --build --preset clang
ctest --preset clang
```

Build trees go to `build/<preset>`. The presets turn `EQVAR_WERROR` on. `msvc`
must run inside a Visual Studio developer prompt. `QP_CXX26=ON` (the
`gcc16-cxx26` preset) compiles with C++26 and uses contracts and
`std::simd` where the compiler reports them; results are the same as the
C++23 build. CMake 3.25 or newer is required.

the median cost of an empty timed call is subtracted. The output gives

per kernel (engine, kernel, compiler, flags, cpu, date, percentiles). Under
WSL2 the hypervisor adds scheduling jitter that shows up in p99.9 and max.

## Limitations

- Option VaR holds each option at today's implied vol unless you call the
  `_vol` drivers with a vol block, and takes European options only. Its linear
  legs use `w . r` on log returns like the rest of this engine; the Python
  `LinearLeg` uses the simple return `S (e^x - 1)`.
- The bootstrap SE dominates the Monte Carlo time (n_boot selections over
  the full scenario set).
- The Monte Carlo runs on one thread.
- `try_cholesky_lower` has no PSD repair; repair a covariance with
  `cholesky(cov, Repair)` or `repair_covariance` before the hot path.

## Option VaR (full revaluation)

The plain idea: a linear book's scenario P&L is a dot product, but an option's
is not, so the honest way to get its VaR is to reprice it in every scenario
and read the tail off those prices.

`option_reval` has the pieces: Black-Scholes-Merton pricing with a carry
yield (dividend yield), closed-form Greeks (delta, gamma, vega, vanna, volga,
theta; Hull, OFOD 11th ed., ch. 19), full-revaluation P&L per scenario and
the delta-gamma approximation, all mirroring `eq_var.revaluation`. Two
drivers put them into the VaR pipeline:

- `historical_option_var_es(legs, exposures, factor_returns, alpha, dt)`:
  each of the T >= 50 historical rows is a scenario. Every leg is repriced
  at `S e^x` with `tau - dt` left to expiry, the linear `w . r` is added, and
  VaR and ES come from the same order statistic as `historical_var`.
- `monte_carlo_option_var(legs, exposures, cov, alpha, n_paths, dist, df,
  seed, n_boot, repair, dt)`: simulates with `simulate_factor_returns` (same
  model, seed and repair as `monte_carlo_var`), reprices every path the same
  way, and returns VaR, ES and both standard errors.

Worked example: ten long 3-month ATM calls on a 100 stock (vol 20 %, r = 2 %)
with a 1 % daily factor vol. The exact 99 % one-day VaR is 11.35 and ES is
12.79; 200,000 paths give both within Monte Carlo error. The delta-normal
VaR of the same book is larger, because positive gamma cuts the downside;
for the short book the ordering flips (`test_option_var.cpp`).

Vol scenario modes. `full_revaluation_pnl(legs, x, dv, n_factors, dt, mode,
skews)` takes `VolMode::StickyStrike` (`sigma + dv`), `StickyDelta`
(`sigma - skew x + dv`, `skews` one per leg or empty) or `HistoricalAtm`
(`sigma e^{dv}`, `dv` a historical log change of ATM vol). The five-argument
overload is sticky strike. All three are pinned to the Python reference at
1e-12 relative (`VolModesGolden` in `test_option_reval.cpp`).

The VaR drivers take vol scenarios too, on what we call the combined axis.
The plain idea: a vol shock is just one more risk factor, so it goes in the
same panel (or covariance) as the spot returns, after them. Formally, with J
spot factors the panel has 2J columns: spot log returns in columns 0..J-1,
then the vol shock of factor j in column J + j (vol points for sticky strike
and sticky delta, a log change of ATM vol for historical ATM).
`exposures` and `leg.factor` still index the J spot factors. For Monte Carlo
the covariance is 2J x 2J, so the spot-vol correlation (the leverage effect,
usually negative for equities) is simulated, not assumed away. With sticky
strike and an all-zero vol block every driver gives the old answer bit for
bit. Worked example: the two-leg test book with vol shocks of a few vol
points a day has 99 % historical VaR 39.22 sticky strike, 39.86 sticky delta
(skews -0.1, -0.2) and 34.80 historical ATM, against 33.44 with vol held
fixed; all three match Python at 1e-11 relative.
Entry points: `option_book_pnl_vol`, `historical_option_var_es_vol(legs,
exposures, combined, alpha, dt, mode, skews)` and
`monte_carlo_option_var_vol(legs, exposures, joint_cov, alpha, n_paths, dist,
df, seed, n_boot, repair, dt, mode, skews)`; tests in `test_option_var.cpp`
(`OptionVarVol.*`), including a closed-form Monte Carlo check on a vol-only
book.

Parity with Python. The historical numbers are pinned to the Python
reference (`eq_var.revaluation.full_revaluation_pnl` followed by the S2 order
statistic) at 1e-11 relative, for an options-only book and for options plus
a linear book, with and without ageing (`dt = 1/252`). The goldens come from
[`cpp/equity-var-engine/tools/gen_option_var_golden.py`](../../cpp/equity-var-engine/tools/gen_option_var_golden.py),
which builds a closed-form scenario panel so no RNG is shared. Monte Carlo
cannot match numpy draw for draw, so its test uses a case with a known
answer: a long call on one normal factor has P&L monotone in the factor, so
the exact VaR is minus the P&L at sigma z_alpha and the exact ES is a
one-dimensional integral. The engine must land within 4 bootstrap standard
errors (ES within 2 %). A book with no option legs goes down the unchanged
linear path, and the tests check the two give identical bits.
