# Equity Options Pricing Engine (C++20)

High-performance C++ twin of the Python reference package
[`eq_options`](../../python/equity/01-options-pricing/) — the same models,
the same conventions, cross-validated against golden vectors *generated by
the Python project*. Where the Python package is the research reference,
this engine is the production-shaped implementation: ~16 million analytic
prices per second on a single core, warnings-as-errors, zero dependencies
beyond the standard library (GoogleTest for tests only).

## Models

| Header (`include/eqopt/`) | Contents |
|---|---|
| `black_scholes.hpp` | European call/put with continuous dividend yield `q`; `d1`/`d2`; erfc-based normal CDF for tail stability; documented `T=0` / `sigma=0` limits |
| `greeks.hpp`        | Analytic delta, gamma, vega, theta, rho, vanna, volga; templated central finite-difference Greeks for *any* pricer |
| `implied_vol.hpp`   | Bracketed Newton with bisection fallback; rejects sub-intrinsic prices; 1e-10 price tolerance |
| `binomial.hpp`      | CRR tree, European + American, dividend yield, O(n)-memory single-vector backward induction |
| `black76.hpp`       | Options on forwards/futures: price + Greeks; exactly equals BSM at `F = S e^{(r-q)T}` |
| `monte_carlo.hpp`   | GBM exact scheme; `std::mt19937_64` explicit seed; antithetic + control variates; `{price, std_error, ci_low, ci_high}`; bit-reproducible given (seed, threads) |

Conventions (identical to the Python reference): continuously compounded
annualised `r`/`q` (ACT/365F), `T` in years, `sigma` annualised; theta per
**year**, vega per **unit** of vol, rho per **unit** of rate. Invalid inputs
(negative `S`, `K`, `T`, `sigma`, NaN) throw `std::invalid_argument`.

## Build, test, benchmark

```sh
cmake -S . -B build && cmake --build build -j
ctest --test-dir build --output-on-failure   # 48 tests, all passing
./build/eqopt_bench
```

Toolchain: C++20, g++ 13, CMake >= 3.20, GoogleTest (system), flags
`-Wall -Wextra -Werror -O2`.

## Cross-language golden validation (the headline)

`tools/gen_golden_header.py` converts the Python project's committed
`tests/golden/golden_vectors.json` (32 cases: price + delta/gamma/vega/
theta/rho across ATM/ITM/OTM, short/long expiry, negative rates, dividend
yields) into `tests/golden_vectors.hpp`. The GoogleTest suite requires every
number to match the Python reference to **1e-9 abs/rel**; the measured
worst-case deviation is **5.3e-15** — i.e. Python and C++ agree to within a
few ulps. See [docs/VALIDATION.md](docs/VALIDATION.md).

Also enforced: put-call parity to 1e-12 across a 486-point grid, Black-76 ==
BSM on the forward to 1e-12, CRR -> BSM convergence (2000 steps within
2e-3, error decaying with n), American >= European with `q=0` American call
== European, Monte Carlo within 3 standard errors with effective variance
reduction and bitwise seed reproducibility, analytic vs finite-difference
Greeks to 1e-6 rel, implied-vol round trips to 1e-8, and a NaN-free domain
scan over extreme inputs.

## Benchmark (g++ 13, `-O2`, 2 vCPU container, single run)

| Kernel | Work | Time | Throughput |
|---|---|---|---|
| Black-Scholes analytic | 1,000,000 prices | 62.4 ms | **16.0M prices/sec** |
| Full analytic Greek set | 100,000 evals | 8.1 ms | 12.3M evals/sec |
| CRR tree, n=1000, European | 1 tree | 0.41 ms | 2,434 trees/sec |
| CRR tree, n=1000, American | 1 tree | 5.25 ms | 191 trees/sec |
| Monte Carlo, 1M paths (antithetic+CV), 1 thread | 1 price + CI | 65.4 ms | 15.3M paths/sec |
| Monte Carlo, 1M paths, 4 threads | 1 price + CI | 46.7 ms | 21.4M paths/sec |

Indicative single-run numbers on a shared 2-vCPU machine; rerun
`./build/eqopt_bench` locally. For desk context (why ~60 ns/price matters)
see [docs/DESK_GUIDE.md](docs/DESK_GUIDE.md).
