# FX Options Pricing Engine (C++20)

High-performance C++ twin of the Python reference project
[`python/fx/01-options-pricing`](../../python/fx/01-options-pricing/) —
identical semantics, cross-validated case-by-case against golden vectors
generated by the Python implementation.

Everything prices European (and, in the tree, American) vanilla FX options
under Garman–Kohlhagen: Black–Scholes with the continuous dividend yield
replaced by the foreign interest rate.

## Conventions

* Pairs are quoted **BASE/QUOTE** (EURUSD = USD per 1 EUR).
* `S` is spot in domestic (quote) currency per unit foreign (base) currency;
  all premiums are domestic currency per unit of foreign notional.
* `r_d` = domestic (quote-ccy) rate, `r_f` = foreign (base-ccy) rate, both
  continuously compounded, annualised, ACT/365F. Negative rates are legal.
* Theta is per year; vega per unit of vol. Unit conventions match the
  Python reference exactly (proven by the golden suite).
* Invalid inputs throw `std::invalid_argument` with an informative message
  (mirror of the Python `ValueError` contract).

## Build, test, benchmark

```sh
cmake -S . -B build
cmake --build build -j
ctest --test-dir build --output-on-failure   # 79 tests, all green
./build/fxopt_bench
```

Requires g++ ≥ 13 (C++20), CMake ≥ 3.20, and a system GoogleTest
(`find_package(GTest REQUIRED)`). No other dependencies.

## Quick example

```cpp
#include "fxopt/garman_kohlhagen.hpp"
#include "fxopt/deltas.hpp"
#include "fxopt/greeks.hpp"

using namespace fxopt;

// EURUSD 6m call: S=1.10, K=1.12, r_d(USD)=4.25%, r_f(EUR)=2.90%, vol 9.25%
double px = gk_price(1.10, 1.12, 0.5, 0.0425, 0.0290, 0.0925, OptionType::Call);
GreeksResult g = analytic_greeks(1.10, 1.12, 0.5, 0.0425, 0.0290, 0.0925,
                                 OptionType::Call);
// 25-delta strike under the premium-adjusted spot convention (Brent solve
// on the market-standard high-strike branch):
double k25 = strike_from_delta(0.25, 1.10, 0.5, 0.0425, 0.0290, 0.0925,
                               OptionType::Call, DeltaConvention::SpotPa);
```

## Validation headline

All **30 golden cases** (price, spot/forward delta, gamma, vega, theta,
rho_domestic, rho_foreign) generated by the Python reference reproduce to
**better than 1e-9** — most to 1e-13 or below. On top of that: put–call
parity and GK == Black-76 to 1e-12, foreign–domestic symmetry across an
81-point grid, strike-from-delta round trips to 1e-8 in all four quoting
conventions, tree convergence to GK, MC agreement to 3 standard errors, and
analytic-vs-finite-difference Greeks to 1e-6. See
[docs/VALIDATION.md](docs/VALIDATION.md).

## Benchmark results

Single thread, g++ 13.3 `-O2`, x86-64 Linux (order-of-magnitude figures;
rerun `./build/fxopt_bench` on your hardware):

| Benchmark | Throughput |
|---|---|
| Garman–Kohlhagen vanilla price + Greeks-free premium | **12.9 M prices/s** (1M prices in 0.077 s) |
| Strike-from-delta, spot / forward (analytic `N^{-1}`) | 7.5 – 8.0 M solves/s |
| Strike-from-delta, premium-adjusted (Brent, branch-aware) | 0.67 – 0.76 M solves/s |
| Monte Carlo, antithetic + control variate | **10.1 M paths/s** (1M paths in 0.099 s, SE ≈ 3e-5) |

At these rates a full 2,000-instrument pricing tile refresh costs ~0.15 ms
and a five-point smile strike solve (2 PA wings + 2 unadjusted + DNS ATM)
costs ~3 µs — comfortably inside e-trading quoting budgets
(see [docs/METHODOLOGY.md](docs/METHODOLOGY.md)).
